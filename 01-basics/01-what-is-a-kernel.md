# 커널이란?

커널은 운영체제의 핵심 부분으로 프로그램이 CPU나 메모리 같은 자원을 사용할 수 있도록 관리한다

프로그램이 실행되려면 CPU가 명령어를 처리하고 메모리에 코드와 데이터를 저장해야 하고  
파일을 읽거나 외부 장치와 데이터를 주고받을 때는 저장장치와 입출력 장치도 사용한다

여러 프로그램이 실행되면 이런 자원을 함께 사용하게 되는데 각 프로그램이 하드웨어를 마음대로 제어하면 서로의 작업을 방해하거나 다른 프로그램의 데이터를 손상시킬 수 있다

그래서 커널이 자원 사용 상태를 관리하고 프로그램마다 사용할 수 있는 범위를 정해 서로의 실행을 보호한다

## 커널의 주요 역할

프로세스는 실행 중인 프로그램을 운영체제가 관리하는 단위이며  
각 프로세스에는 사용하는 메모리와 현재 실행 상태 같은 정보가 함께 관리된다  
같은 프로그램이라도 여러 프로세스로 실행될 수 있다

커널은 여러 프로세스가 함께 사용하는 자원을 다음과 같이 관리한다

| 역할 | 설명 |
| --- | --- |
| 프로세스 관리 | 실행 가능한 작업을 선택하고 CPU 사용 시간을 배분한다 |
| 메모리 관리 | 프로그램이 사용하는 메모리를 관리하고 프로세스 사이의 메모리 접근을 보호한다 |
| 장치 관리 | 장치 드라이버를 통해 키보드, 디스크 등의 하드웨어를 제어한다 |
| 프로그램의 요청 처리 | 파일 입출력처럼 프로그램이 커널에 요청한 작업을 처리한다 |

여러 프로세스가 CPU를 사용하려고 하면 커널은 실행 가능한 작업 중 무엇을 먼저 실행할지 정하는데  
이렇게 실행할 작업을 선택하고 CPU를 배분하는 것을 스케줄링이라고 한다

따라서 프로그램을 실행했다고 해서 CPU를 계속 독점하는 것은 아니다

메모리도 여러 프로그램이 함께 사용하는 자원이기 때문에 관리가 필요하며 커널은 각 프로그램이 사용할 메모리를 관리하면서 다른 프로세스의 메모리를 함부로 읽거나 바꾸지 못하게 한다  
필요한 경우에는 정해진 방법으로 메모리를 공유할 수도 있다

장치는 종류마다 제어 방법이 달라 장치 드라이버를 사용하는데  
드라이버가 장치와 통신하고 필요한 명령을 전달하므로 프로그램은 장치별 제어 방법을 모두 직접 구현하지 않아도 된다

대신 프로그램은 커널이 제공하는 정해진 사용 방법을 따르는데 이처럼 기능을 사용하거나 요청할 수 있도록 정해 둔 방식을 인터페이스라고 한다

## 자원의 추상화

하드웨어를 직접 다루려면 내부 구조와 동작 방법을 알아야 하는데  
프로그램이 매번 이런 세부 사항까지 처리하면 코드가 복잡해지기 때문에 커널은 자원을 사용하기 편한 형태로 제공한다

예를 들어 프로그램은 디스크의 물리적인 저장 위치를 직접 다루는 대신 파일이라는 단위로 데이터를 읽고 쓰기 때문에  
파일이 디스크의 어디에 저장되어 있는지 몰라도 파일을 열고 내용을 읽을 수 있다

메모리에서도 이런 방식을 사용하는데 프로그램이 사용하는 주소를 가상 주소라고 하고 실제 메모리의 위치를 나타내는 주소를 물리 주소라고 한다  
여기서 프로그램에 주어진 가상 주소의 범위가 가상 주소 공간이다

프로그램이 가상 주소 공간을 사용하면 물리 메모리의 구체적인 배치를 직접 다룰 필요가 줄어들고  
주소 변환은 커널이 관리하는 정보를 이용해 CPU가 수행한다

이처럼 복잡한 내부 구조를 감추고 사용하기 쉬운 방법을 제공하는 것을 추상화라고 하며  
프로그램은 제공된 인터페이스를 사용하므로 하드웨어마다 다른 세부 사항을 모두 처리하지 않아도 된다
