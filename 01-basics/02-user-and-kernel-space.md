# 사용자 공간과 커널 공간

리눅스에서는 일반 프로그램이 사용하는 사용자 공간과 커널이 사용하는 커널 공간을 나누어 두는데  
사용자 공간에는 일반 프로그램의 코드와 데이터가 들어가고 커널 공간에는 커널의 코드와 시스템 관리에 필요한 데이터, 커널 드라이버 등이 들어간다

일반 프로그램이 커널의 데이터를 잘못 바꾸면 커널이 관리하는 다른 프로그램이나 시스템 전체에 영향을 줄 수 있기 때문에  
일반 프로그램이 커널 공간에 직접 접근하지 못하도록 보호한다

| 구분 | 사용자 공간 | 커널 공간 |
| --- | --- | --- |
| 내용 | 일반 프로그램의 코드와 데이터 | 커널의 코드와 데이터, 커널 드라이버 등 |
| 접근 제한 | 각 프로그램이 자신에게 허용된 메모리에 접근할 수 있다 | 일반 프로그램이 직접 접근할 수 없도록 보호된다 |

사용자 공간에 있는 메모리도 모든 프로그램이 자유롭게 접근할 수 있는 것은 아니며  
프로세스마다 사용할 수 있는 주소 공간과 권한이 정해져 있기 때문에 자신에게 허용된 메모리를 사용해야 한다

각 프로세스의 주소 변환 정보에 따라 주소가 연결되는 위치가 달라질 수 있기 때문에  
서로 다른 프로세스에서 같은 가상 주소를 사용하더라도 실제로는 다른 물리 메모리를 가리킬 수 있다

이런 접근 제한은 CPU의 실행 권한과도 관련되어 있는데  
사용자 공간과 커널 공간이 메모리 영역을 나누는 개념이라면 사용자 모드와 커널 모드는 CPU의 실행 권한을 나누는 개념이다

일반 프로그램은 권한이 제한된 사용자 모드에서 실행되므로 커널 메모리에 직접 접근하거나 시스템을 제어하는 일부 명령을 실행할 수 없고  
커널 코드는 자원 관리와 장치 제어에 필요한 권한을 가진 커널 모드에서 실행된다

그래서 일반 프로그램이 직접 할 수 없는 작업은 커널에 요청해야 하는데 이때 사용하는 인터페이스가 시스템 콜이다  
파일 읽기처럼 커널의 도움이 필요한 작업도 이 방법으로 요청한다

프로그램이 시스템 콜을 사용하면 커널 모드에서 요청을 처리하는 커널 코드가 실행되고 처리가 끝나면 사용자 모드로 돌아와 프로그램의 실행을 이어간다

이때는 프로그램이 전달한 요청을 커널 코드가 확인하고 처리할 뿐 일반 프로그램의 코드에 커널 권한을 주는 것은 아니다  
이런 방식으로 커널 공간에 직접 접근하지 않아도 필요한 기능을 사용할 수 있다
