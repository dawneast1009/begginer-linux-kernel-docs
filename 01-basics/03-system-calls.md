# 시스템 콜이란?

시스템 콜은 사용자 프로그램이 커널에 작업을 요청할 때 사용하는 인터페이스다  
일반 프로그램은 커널이 관리하는 자원을 마음대로 조작할 수 없으므로 파일 읽기와 쓰기, 프로세스 생성 같은 작업을 시스템 콜로 요청한다

프로그램마다 자원 상태나 접근 권한을 따로 판단하면 서로 충돌하거나 보호가 제대로 이루어지지 않을 수 있기 때문에  
여러 프로그램이 함께 사용하는 자원은 같은 기준으로 관리해야 한다

커널은 시스템 콜로 전달받은 요청과 처리에 필요한 정보를 확인한 뒤 작업을 수행하는데  
이 과정에서 요청을 실행해도 되는지 함께 검사하므로 프로그램이 요청했다고 모든 작업이 허용되는 것은 아니다

## 라이브러리를 통한 시스템 콜 사용

라이브러리는 프로그램에서 사용할 수 있는 함수 등을 모아 둔 소프트웨어로  
프로그램은 보통 라이브러리에서 제공하는 함수를 통해 시스템 콜을 사용하며 라이브러리는 요청을 커널에 전달할 수 있는 형태로 준비하고 처리 결과를 돌려준다

파일을 읽을 때 사용하는 read()도 이런 함수 중 하나이며 호출할 때는 읽을 대상과 데이터를 저장할 메모리 주소, 읽으려는 최대 크기를 지정한다

이처럼 함수에 전달하는 값을 인자라고 하고 읽은 데이터를 담아 둘 메모리 영역을 버퍼라고 하는데  
프로그램이 필요한 정보를 인자로 전달하면 라이브러리는 그 정보를 이용해 시스템 콜을 실행한다

## 시스템 콜의 동작 과정

read()를 호출한 뒤 요청이 처리되는 과정을 단순화하면 다음과 같다

1. 프로그램이 읽을 대상과 버퍼, 읽을 크기를 인자로 전달해 read()를 호출한다
2. 라이브러리가 시스템 콜에 필요한 정보를 준비해 커널에 전달한다
3. CPU가 커널 모드로 전환되고 커널이 요청을 확인한다
4. 커널이 읽기 작업을 처리하고 데이터를 지정한 버퍼에 저장한다
5. 처리 결과를 반환하고 사용자 모드로 돌아온다

커널이 작업을 처리하려면 어떤 요청인지 구분할 수 있어야 하므로  
라이브러리는 시스템 콜을 구분하는 번호와 필요한 인자를 정해진 방식으로 전달하고 커널은 이를 바탕으로 요청을 처리한다

읽기 작업에서는 요청이 유효한지, 데이터를 저장할 메모리에 접근할 수 있는지 등을 확인하며  
전달받은 정보에 문제가 있으면 작업을 처리하지 못하고 오류를 반환할 수 있다

## 시스템 콜의 처리 결과

시스템 콜을 사용한 뒤에는 요청이 어떻게 처리되었는지 확인해야 하는데  
함수가 작업을 마친 뒤 돌려주는 값인 반환값을 보고 처리 결과를 확인할 수 있다

성공했을 때 어떤 값을 반환하는지는 함수마다 다르다

read()는 실제로 읽은 바이트 수를 반환하며 요청한 크기보다 적게 읽어도 반드시 오류를 뜻하는 것은 아니다  
일반 파일의 끝에 도달하면 0을 반환한다

오류가 발생하면 read()는 -1을 반환하므로  
프로그램은 반환값과 오류 정보를 확인해 작업을 이어가거나 오류를 처리한다

이런 실패 원인은 시스템 콜마다 달라서  
요청한 작업에 따라 접근 권한이 부족하거나 대상이 존재하지 않거나 인자가 잘못된 경우 등에 실패할 수 있다

## 시스템 콜이 필요하지 않은 작업

read()는 라이브러리 함수를 통해 시스템 콜을 사용하지만 모든 함수가 시스템 콜을 사용하는 것은 아니다  
이미 접근할 수 있는 메모리에서 계산하거나 데이터를 처리하는 작업은 커널에 별도로 요청하지 않고 수행할 수 있다

예를 들어 strlen()은 문자열 끝의 널 문자를 제외한 바이트 수를 구하는 함수인데  
접근할 수 있는 문자열의 길이를 계산하는 작업이므로 계산 자체에는 시스템 콜이 필요하지 않다

따라서 함수를 호출했다고 항상 커널 코드가 실행되는 것은 아니며 시스템 콜이 필요한지는 그 함수가 실제로 어떤 작업을 하는지에 따라 달라진다
