# VFS란?

파일 시스템은 파일의 데이터와 디렉터리 구조, 소유자와 권한 같은 정보를 관리하며  
파일 시스템마다 이런 정보를 저장하고 찾는 방식은 다를 수 있지만 프로그램에서는 파일을 일정한 방법으로 사용할 수 있어야 한다

프로그램이 파일 시스템마다 다른 내부 구조를 직접 처리해야 한다면 파일을 다루는 코드가 복잡해지고 새로운 파일 시스템을 사용할 때마다 그에 맞는 처리 방법도 알아야 할 수 있다  
이런 차이가 있어도 파일을 같은 방식으로 다룰 수 있게 해주는 커널 내부 계층이 VFS(Virtual File System)다

VFS는 공통된 사용 방법인 인터페이스를 제공하고 요청을 해당 파일 시스템의 동작으로 연결하므로  
프로그램은 open()으로 파일을 열고 read()로 읽고 write()로 쓰면 되므로 각 파일 시스템이 내부에서 데이터를 어떻게 저장하는지까지 알 필요는 없다

## VFS와 파일 시스템의 역할

VFS는 파일과 디렉터리를 공통된 형태로 다루고 파일 작업에 사용할 인터페이스를 제공하며  
각 파일 시스템은 이 인터페이스에 맞춰 실제로 실행할 동작을 구현하고 VFS는 필요한 동작을 호출할 수 있도록 연결한다

파일 경로를 찾을 때도 VFS와 해당 파일 시스템의 동작이 함께 사용되는데  
VFS는 메모리에 보관해 둔 탐색 정보인 캐시를 활용하고 필요한 경우에는 해당 파일 시스템의 함수를 호출해 탐색을 이어간다

이런 과정을 통해 서로 다른 파일 시스템의 파일도 공통된 방식으로 찾고 사용할 수 있다  
다만 VFS가 파일 시스템의 저장 형식 자체를 바꾸는 것은 아니고 내부 동작이 달라도 프로그램에서는 같은 방법으로 사용할 수 있게 해주는 것이다

## 시스템 콜과 VFS의 관계

시스템 콜은 사용자 프로그램의 요청을 커널로 전달하는 인터페이스로  
프로그램이 어떤 파일에 무엇을 할지 지정해 요청하면 커널 내부의 VFS는 그 요청을 파일 시스템에 맞는 동작으로 연결한다

시스템 콜과 VFS는 담당하는 범위에도 차이가 있는데  
시스템 콜은 파일 작업뿐 아니라 프로세스 생성 같은 요청에도 사용되지만 VFS는 파일 시스템과 관련된 기능을 커널 안에서 공통된 방식으로 다루는 계층이다

## 파일 접근 권한과의 관계

공통된 인터페이스를 제공한다고 모든 파일에 접근할 수 있는 것은 아니며  
파일을 열거나 데이터를 읽을 때는 각 작업에 필요한 권한과 조건이 있으며 이를 만족하지 못하면 작업이 실패할 수 있다

VFS를 통해 파일을 사용할 때도 이런 접근 제어가 적용된다
