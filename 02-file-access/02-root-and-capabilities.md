# 일반 사용자와 root의 실행 결과가 다른 이유

같은 명령어도 어떤 사용자와 권한으로 실행했는지에 따라 결과가 달라질 수 있는데  
명령어를 실행하는 프로세스는 자신의 권한으로 작업을 요청하고 커널은 해당 프로세스가 대상에 접근하거나 요청한 작업을 수행할 수 있는지 확인한다

사용자를 구분하는 번호가 UID이고 그룹을 구분하는 번호가 GID이며  
기본 그룹 외에 추가로 속한 보조 그룹의 정보도 권한을 확인할 때 함께 사용한다

root는 UID가 0인 사용자이며 일반적으로 시스템 관리에 필요한 여러 권한을 가진다 다만 일반 사용자와 root의 차이를 이해하려면 UID뿐 아니라 어떤 권한을 가지고 있는지도 살펴봐야 한다

프로세스에는 특정 작업을 허용하는 세부 권한인 capability가 주어질 수도 있는데 이런 사용자,그룹 정보와 권한 정보를 프로세스의 자격 정보라고 한다  
같은 명령어라도 프로세스의 자격 정보가 다르면 할 수 있는 작업이 달라질 수 있는 것이다

## 파일 접근 권한을 판단하는 과정

cat 명령어로 파일을 읽을 때도 시스템 콜을 통해 파일을 열고 읽는 작업을 커널에 요청하는데  
커널은 프로세스의 사용자,그룹 정보와 파일의 소유자,권한 정보 등을 보고 접근을 허용할지 판단한다

이때 어떤 작업을 요청했는지도 중요하다 파일을 읽을 때와 쓸 때 필요한 권한은 다르고 파일을 읽을 수 있다고 소유자까지 바꿀 수 있는 것은 아니기 때문에 같은 파일이라도 요청한 작업에 따라 결과가 달라질 수 있다

파일 자체의 권한만 확인하는 것도 아니다  
파일 경로를 따라가면서 거치는 디렉터리를 탐색할 권한이 있는지도 확인하므로 파일에 읽기 권한이 있어도 상위 디렉터리를 탐색할 수 없으면 파일을 열지 못할 수 있다

일반적인 파일 권한으로 접근할 수 없다면 관련 capability가 있는지도 확인하는데  
예를 들어 CAP_DAC_READ_SEARCH가 있으면 파일 읽기와 디렉터리 탐색 권한 검사를 우회할 수 있다

이런 권한 검사는 커널에서 이루어지므로 같은 명령어를 사용해도 프로세스의 권한에 따라 접근이 허용되거나 거부될 수 있다  
단순히 명령어가 무엇인지보다 어떤 권한으로 요청했는지가 실행 결과에 영향을 주는 것이다

## Capability란?

리눅스에서는 원래 root가 갖던 권한을 capability라는 여러 세부 권한으로 나누어 관리하며  
이렇게 나누면 파일 읽기나 소유자 변경처럼 특정 작업에 필요한 권한만 따로 줄 수 있다

| Capability | 허용하는 작업 |
| --- | --- |
| CAP_DAC_READ_SEARCH | 파일 읽기와 디렉터리 탐색 권한 검사 우회 |
| CAP_CHOWN | 파일의 소유자와 그룹을 임의로 변경 |
| CAP_KILL | 프로세스에 사건을 알리는 시그널 전송 시 권한 검사 우회 |

예를 들어 일반 사용자는 자신이 소유한 파일이라도 소유자를 다른 사용자로 자유롭게 변경할 수 없지만  
CAP_CHOWN 권한이 있는 프로세스는 소유자를 변경할 수 있다

프로세스에 종료 요청 같은 사건을 알리는 방법을 시그널이라고 하는데  
다른 사용자의 프로세스에 시그널을 보내는 작업도 권한 검사를 받는데 CAP_KILL이 있는 프로세스는 이때의 일반적인 권한 검사를 우회할 수 있다

이처럼 파일 읽기, 소유자 변경, 시그널 전송은 각각 다른 권한과 관련되어 있으므로 하나의 capability가 있다고 다른 특권 작업까지 전부 할 수 있는 것은 아니다  
필요한 capability를 받으면 일반 사용자로 실행한 프로세스도 해당 특권 작업을 할 수 있다

root로 실행한 프로세스라도 capability가 제한되어 있으면 일부 작업을 하지 못할 수 있다  
또한 SELinux처럼 별도의 접근 제한 정책을 적용하는 보안 기능이 작업을 막을 수도 있으므로 실제로 허용되는 작업은 이런 조건까지 함께 확인해야 한다

## root 권한과 커널 모드의 차이

root 권한은 프로세스가 어떤 작업을 할 수 있는지를 나타내고 커널 모드는 CPU가 커널 코드를 실행할 때 사용하는 실행 모드다 둘 다 권한과 관련되어 있지만 같은 개념은 아니다

root로 실행한 일반 프로그램도 자신의 코드는 사용자 모드에서 실행하며  
커널의 기능이 필요할 때는 일반 사용자 프로그램과 마찬가지로 시스템 콜을 사용한다

일반 사용자 프로그램이 시스템 콜을 호출해도 요청을 처리하는 커널 코드는 커널 모드에서 실행되지만  
커널은 요청한 프로세스의 권한을 기준으로 작업을 허용할지 판단하므로 커널 모드로 전환되었다고 해당 프로세스가 root 권한을 얻는 것은 아니다
